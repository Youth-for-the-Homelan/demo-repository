# BOOGYEMAN Swarm Workshop — بروتوكول السرب

هذه التجربة هي **إضافة معزولة** داخل فرع منفصل. لم تُعدّل ملفات التطبيق الحالي في `main`. وهي تحوّل فكرة البوتات الشبيهة بالعناكب والنمل إلى حلقة مرشحين محدودة يمكن اختبار منطقها تلقائيًا.

## المفكرة الأصلية — البنود الستة محفوظة

1. **بوتات تحمل عدة أكواد عشوائية داخل مشروع وتجربها حتى ينجح كود:** يولّد المحرك مرشحين متعددين من قوالب مضبوطة بترتيب شبه عشوائي، ويفحصهم بالتتابع حتى ينجح مرشح أو ينتهي حد المحاولات.
2. **العناكب:** بوت الاستكشاف يساعد في تقسيم الهدف إلى خيوط عمل واعتماديات.
3. **النمل:** بوت التنسيق يوزع الأولويات ويتبادل نتائج المحاولات لتقليل تكرار الجهد.
4. **المشاريع تنشأ من البوتات:** النجاح ينتج artifact مشروعًا منظمًا يحتوي README ومصدر المرشح وتقرير الفحوص؛ يحتاج ربط هذا الناتج بمشغّل/مخزن حقيقي قبل اعتباره مشروعًا منشورًا.
5. **تشغيل وإيقاف:** حلقة التشغيل تقبل `AbortSignal` للإيقاف، ولكل بوت حالة `enabled`، وحد المحاولات يصل إلى 24، وحد السكان 20.
6. **تعمل في أي بيئة:** صُممت المخرجات كملفات نصية مستقلة يمكن نقلها، لكن كل بيئة (Browser / GitHub Actions / VM / Container) تحتاج adapter واختبارات خاصة بها؛ لا ندّعي دعمًا عالميًا بدونها.

## ما الذي ينفذه هذا النموذج؟

- يستقبل هدفًا، يتتبع البوتات الفعّالة، ويمرر المهمة عبر دور الاستكشاف والتنسيق.
- يخلط مجموعة قوالب بترتيب شبه عشوائي قابل لإعادة الإنتاج لرقم تشغيل ثابت.
- يفحص توازن الأقواس، وجود مدخل مصدّر، الأنماط المحظورة، حد الحجم، وعقد المهمة.
- يرفض المرشحين غير المطابقين، ويتوقف عند أول مرشح يجتاز الفحوص أو عند بلوغ حد المحاولات.
- ينشئ بوتًا فرعيًا بميزانية توليد محدودة، وينتج artifact مشروعًا وتقرير تحقق.
- يعيد حالات واضحة `BLOCKED`, `STOPPED`, `NO_CANDIDATE_PASSED`, و`CANDIDATE_ACCEPTED_STATIC_ONLY`.

## تشغيل الاختبارات

يتطلب Node.js حديثًا دون مكتبات خارجية:

```bash
node --test experiments/boogyeman-swarm/engine.test.mjs
```

سيعمل GitHub Actions في هذا الفرع على تشغيل الاختبارات عند تغيير ملفات السرب. صلاحيات الـ workflow قراءة فقط، ولا يحتاج إلى أسرار.

## حاجز مهم: الاختبار الساكن ليس تشغيلًا

**لا يستخدم هذا النموذج `eval` أو `Function` لتشغيل المرشح.** القوالب المضمنة هي مصدر النص المولّد، ويتم تحليل بنيتها فقط. عندما يجتاز المرشح الفحوص، فهذا لا يعني أنه تُرجم أو عمل في وقت التشغيل. تقرير المشروع يذكر صراحةً `Runtime execution: NOT EXECUTED`.

أي مرحلة لاحقة لتشغيل الشيفرة يجب أن تستخدم عاملًا مؤقتًا معزولًا بصلاحيات دنيا، وحدود وقت وذاكرة ومساحة تخزين وحجم مخرجات، وشبكة معطلة افتراضيًا، ومن دون أسرار. ولا ينبغي مطلقًا تشغيل شيفرة مساهمات غير موثوقة في workflow مميز يملك مفاتيح/أسرارًا. راجع [GitHub security guidance](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target).
